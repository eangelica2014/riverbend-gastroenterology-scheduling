## How to Read the Agent Workspace

The **patient surface** intentionally uses plain language and one question at a time. The live transcript helps a caller notice a misheard phrase, but it never acts as identity proof. The progress rail shows where the request is—intent, identity, coverage, policy, availability, confirmation, and outcome—without exposing protected detail. A transfer is presented as a supported next step rather than a failure.

The **FDE evidence surface** answers a different set of questions: which intent was recognized, whether verification passed, which rule IDs authorized or blocked the action, which tool ran, what result returned, and whether a mutation occurred. This is the operational difference between a plausible conversation and a governable agent.

| Evidence label   | Meaning                                   | Hiring-manager question answered                     |
| ---------------- | ----------------------------------------- | ---------------------------------------------------- |
| **Intent**       | Supported workflow or repair path         | Did the agent understand the administrative job?     |
| **Verification** | Candidate lookup and identity state       | Was protected work gated appropriately?              |
| **Rule**         | Versioned clinic policy and reason code   | Why was the action allowed, blocked, or transferred? |
| **Tool**         | Typed read, search, mutation, or transfer | What external action did the system attempt?         |
| **Outcome**      | Structured result or receipt              | What changed, and can it be audited?                 |

## What to Say About the New-Patient Requirement

Riverbend defines a patient as new when the person is new to the practice **or** has not been seen in more than three years. The assignment also limits mock calls to the supplied sample set. The demonstration therefore proves a new-patient visit using Elena Vasquez, whose last visit falls outside the three-year window, and proves the 30-minute rule. A caller with no matching sample record receives a safe retry or front-desk path rather than an invented chart. In production, registration would be a separate authorized workflow with its own identity, consent, coverage, and EHR contract.

## What to Say About Telephony

The assignment explicitly prioritizes rules, design, and iteration over telephony.[1] The submission uses browser speech recognition and synthesis as an optional voice layer over the complete text and scenario interface. This keeps the agent openable without credentials and makes policy and tool evidence inspectable. A production release would add a Retell, Vapi, Bland, LiveKit, Pipecat, or company-standard telephony adapter only after validating interruption, latency, transfer, DTMF, recording/consent, fallback, and failure behavior.

## What to Say About “Self-Learning”

In this healthcare-adjacent context, self-learning means that the platform detects a redacted failure pattern, identifies the likely source/prompt/policy/tool/adapter layer, drafts a source-linked proposal, and reruns regression. It does **not** mean that a live agent rewrites eligibility, identity, provider, or escalation policy. An authorized FDE or clinic owner approves the change; the release remains canary-scoped and rollback-ready.

## Q&A Guide

| Likely question                                         | Concise answer                                                                                                                                                                                            |
| ------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Why not put all clinic rules in the prompt?             | Because fluency cannot guarantee authorization. Versioned deterministic policy is diffable, testable, reusable, and inspectable before a write.                                                           |
| Why is the FDE the primary user rather than the clinic? | The FDE converts operational truth into a live automation and carries integration and release accountability. Clinic owners approve local truth; patients experience the outcome.                         |
| What would you build first?                             | The source-linked policy compiler and generated critical scenarios, because they attack the earliest repeated work and can be falsified quickly.                                                          |
| What would make you stop?                               | Any critical regression from compilation, noisy scenario generation that increases review time, or evidence that the new workflow adds burden without improving time or defect detection.                 |
| How does this improve revenue?                          | It targets shorter time to approved release, lower active FDE hours, faster diagnosis, and faster second-clinic setup while holding critical correctness constant. It does not invent an ARR forecast.    |
| What is not production-ready?                           | Telephony, live EHR/PMS adapters, tenant auth/storage, PHI controls, canary/rollback infrastructure, and real-clinic outcome baselines. Each is represented as a contract or gate, not falsely simulated. |
| How does empathy affect architecture?                   | It changes interaction order and evidence: retain intent, ask one question at a time, show transcript and progress, verify before disclosure, support human handoff, and test negative guarantees.        |

## Closing Position

The submission met the assignment by building the requested agent, documenting its architecture and iteration, and proposing a designed platform with prioritized experiments. It exceeded the assignment by making the whole system inspectable and reproducible: a public prototype, explicit policy and tool contracts, privacy and safety gates, a real-time transcript, evidence-derived progress, a 25-scenario laboratory, 19 deterministic assertions, CI, an editable PRD, an interactive deck, and a role-linked decision framework.

The recommended product decision is disciplined: **fund source-to-policy and policy-to-test first; earn the right to scale reuse and learning.**
